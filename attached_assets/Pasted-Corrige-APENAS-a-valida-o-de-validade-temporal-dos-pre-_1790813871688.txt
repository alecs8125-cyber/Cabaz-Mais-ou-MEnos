ESTADO CONFIRMADO DIRETAMENTE NO SUPABASE:

public.prices possui:

- valid_from timestamptz nullable
- valid_until timestamptz nullable
- captured_at timestamptz not null
- verification_status text not null

verification_status permite:
- verified
- pending
- rejected
- expired

O comparador já exige verification_status = verified.

PROBLEMA CONFIRMADO:

services/prices.ts atualmente considera valid_from e captured_at,
mas NÃO lê/verifica valid_until.

Consequentemente, um preço com:

valid_until < agora

pode atualmente entrar numa comparação.

OBJETIVO:

Um preço só pode ser usado se:

1. verification_status = verified;
2. captured_at <= agora;
3. valid_from é null OU valid_from <= agora;
4. valid_until é null OU valid_until >= agora;
5. todas as validações atuais restantes continuarem válidas.
